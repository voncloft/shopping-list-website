TWELVE INSTANT POT RECIPES — SERVER INSTALL

1. Back up your shopping_list database and the site files you replace.
2. Copy the 24 new HTML files into your site's existing recipes/ingredients/
   and recipes/steps/ folders, keeping their filenames.
3. Import upgrades/import_12_instant_pot_recipes.sql using phpMyAdmin, or run:
   mysql -u YOUR_USER -p shopping_list < upgrades/import_12_instant_pot_recipes.sql
   Run the complete file in one connection, once at a time. Do not use --force.
4. Copy these supplied PHP files into the matching site folders:
   functions/get_prices_and_macros.php
   functions/recipe_nutrition.php
   scripts/show_shopping_list.php
   php/final_shopping_list.php
   These make recipe selection honor Used Servings and label incomplete totals.
5. Open your recipe list. You should see all 12 names below. Open a recipe
   to view its ingredients and numbered instructions.

Do not re-import database_setup into an existing database: it drops tables.
For a new installation, use database_setup first, then this additive import.
The SQL is designed for the MariaDB/MySQL schema in this repository. It creates
the 12 recipe tables, registers them in recipe_lists, adds missing items, and
fills every recipe with its ingredient IDs. It does not change existing foods,
recipes, weekly selections, pantry quantities, or the global servings setting.
Tables are created before the data transaction because MySQL DDL auto-commits.
If interrupted, fix the reported error and rerun; a schema rollback is not promised.
Serial reruns do not duplicate foods or ingredient rows. Do not run two imports
at the same time. Existing rows in these recipe tables are not overwritten.

SERVING SETTINGS
Each recipe is ONE batch making SEVEN meals. Select Portions = 1 when adding
a recipe to the weekly list. Set Portions for Prep = 7 for per-meal totals.
Selecting Portions = 7 makes seven batches, not seven individual meals.

INGREDIENT DATA
Names are matched without case or surrounding spaces. IDs are resolved from
your database; no ingredient IDs are hard-coded. If several names normalize
to the same name, the lowest existing ID is used.
New prices and nutrition fields are NULL (unknown), and servings is 1.
Existing label data, prices, URLs, spelling, and servings remain unchanged.
Enter new-item nutrition from your product labels using the serving units below.
If the package uses a different serving size, adjust the recipe Used Servings
accordingly. Do not trust incomplete totals as complete calorie or macro counts.
Unknown prices may still display as zero in the existing app; zero is not a quote.
Qty counts purchased packages/items. Used Servings counts nutrition servings
consumed in the WHOLE batch. The app divides batch nutrients by the global
Portions for Prep setting. Tap water has Qty 0. Pantry packages may be counted
more than once when several recipes share an ingredient; adjust pantry normally.
Meat Qty 1 means enough packages for the listed raw weight, not a 1 lb package.
US cup = 8 fl oz. Ingredient units below are mapping assumptions: the database
does not store nutrition serving-size text. Verify them against your own labels.
